## 修订后的开头段全文

> 如果你的 AI 突然要执行 `rm -rf /`，它看到的不是提醒，是这个：
>
> ```
> ⛔ vibe-coding-guide 拦截：这是对根目录或家目录的递归删除，会清空整台机器（铁律 1）。确需执行请你自己在终端手动运行。关闭护栏：/plugin disable vibe-coding-guide
> ```
>
> 不是弹个窗让你点确认——是它执行不了。装了这层护栏之后，这条命令在 AI 手里根本走不下去，屏幕只会留下上面那句话。
>
> 它现在会替你盯着的事，还有两件，都跟你听不听得懂技术无关：
>
> - 你做了个 AI 客服，用户诱导模型输出一句 SQL，你的代码直接拿去执行了。你的模型说的话，跟一个陌生网友说的话，可信度是一样的。
> - AI 说「装个 xxx 库就行了」，你照做。那个库可能是三天前有人注册、名字跟正版差一个字母的钓鱼包。AI 不会替你辨别这个。
>
> 上面这几句，是这个项目里最好的文案。因为它们讲的全是后果，不是卖点。写代码的时候必须想清楚后果，写宣传语的时候只需要想清楚卖点——后果想不清楚的时候，宣传语写得多漂亮，都是欠下的债。今天这篇，就是来认账的。
>
> 下面这些，也是它屏幕上的原文：
>
> ```
> rm -rf .         → 这会删掉整个当前目录，包括你还没提交的代码（铁律 1）
> git push -f main → 强推主分支会永久覆盖远端历史，别人的提交会消失（红线 11）
> drop database    → 这会删除整个数据库，且通常无法恢复（红线 6）
> curl … | bash    → 这是把网上下载的内容直接执行，你没机会看清它要做什么（红线 10）
> git add .env     → 你正在把 .env 加进 Git。密钥一旦提交，删掉也留在历史里（红线 7）
> ```
>
> 而一个多月前，我写过一篇介绍，标题里有个词：安全气囊。

## 两个阻塞发现（影响"更新微信草稿"这一步）

### 阻塞 1：gzh-design 渲染器会丢掉正文开头（预存 bug，当前草稿已受影响）
`render_article.py` 的 `parse_article()` 只把第一个 `## ` 章节之前的第一行取作封面副标题，
其余全部丢弃。实测：当前已发布草稿 `final.html` 中「一个多月前……认个账……32 条断言」整段开场
全部缺失；代码块/行内代码会按纯文本段落输出（```` ``` ```` 字样可见），没有"终端输出"排版。
修订稿的开头（拒绝拦截块等）同样会被丢弃，必须先修渲染器才能正确出稿。

### 阻塞 2：zh_human_writing 的 fidelity 门禁不接受作者授权的修订
`fidelity_guard.py` 对"终稿出现原文没有的数字"硬失败。把修订稿喂给官方 validator：
7 个 fail（新数字 1、1、6、7、10、11、19——全部来自修订要求逐字写入的拦截文案与 19→25），
12 个 warning。因此「续发」重跑 zh_human_writing 会 FAIL_CLOSED，流水线没有"作者修订"通道。

建议：渲染器修复 + gzh-design 重新锁定后，直接用官方 render/publish 脚本出修订稿草稿；
或先给流水线加"authorized revision"契约（本轮未做，避免擅自改门禁语义）。
