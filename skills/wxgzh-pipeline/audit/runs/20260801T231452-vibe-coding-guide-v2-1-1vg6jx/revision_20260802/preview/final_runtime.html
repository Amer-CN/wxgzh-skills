01

PART

以前为什么拦不住：它只是一本更厚的书

PART 01

先说我这一路做了什么。

第一刀，省上下文。v1.0 是 33.7 KB 的单文件手册，AI 每次要用，都得把整本书塞进脑子。拆成五个文件，SKILL.md 里放一张路由表，按需只读：问红线读 redlines.md，改老项目读 legacy-audit.md，新项目从零开始读 new-project.md，按项目类型读 scenarios.md，两个 AI 说法打架读 ai-disputes.md。checklist.md 不是拆出来的，它本来就单独存在。以前是每次问路都背整本地图册，现在是先看目录，只翻你要去的那一页。

拆文件还拆出一个事故：redlines.md 把整本手册的总序——也就是符号图例 🟦🟢🟡⛔💡 唯一定义处——一起吞了进去。结果 AI 只读别的文件时，看到 ⛔ 却不知道那是什么意思。拆文件最危险的从来不是内容丢了，是内容还在、但跑到了没人会读的地方。

第二刀，补红线。原来八条红线全是传统 Web 开发的老问题。2026 年的小白项目，十个有九个要接大模型 API，这三类风险一条都没覆盖。新增三条，其中两条开头已经用大白话给你看过——AI 客服被诱导输出 SQL、名字差一个字母的钓鱼包；第三条：你不在电脑前、AI 自己跑的时候，删除、强推、部署、改线上配置，不给无人值守权限。

清单从 19 条扩到 25 条，标出 8 条 ⭐ 最小必查——对应「一旦出事就不可逆」的风险：数据没了、钱算错了、密钥泄了。时间不够，就只跑这 8 条。

但这三刀加起来，还是「请 AI 自觉」。真正让它绕不过去的，是 v2.0 的两件新东西。

02

PART

v2.0：体检脚本 + 强制护栏

PART 02

第一件，体检脚本。bash scripts/audit.sh，把 25 条清单里机器能查的那部分跑一遍，输出 ✅/❌ 和精确到「文件:行号」的结果：密码有没有用弱哈希、金额是不是浮点、.env 有没有被误提交、密钥有没有写死在代码里、有没有 SQL 拼接、有没有静默吞掉报错。

它最诚实的地方是最后那段输出——主动列出「我完全查不了的项」，告诉你哪些必须人工过。一个只报喜的检查工具，比没有检查工具更危险，因为它给你的是虚假的安心。

它第一个误报，报的是它自己。脚本扫「有没有硬编码的密钥」，而它的搜索规则 api[_-]?key 这段文字本身就长得像密钥。任何测量工具都得先把自己排除在外，否则它测的第一个东西，永远是它自己。

顺便说一句，看检查报告也要看分布。今天跑代码检查，报了 277 条问题，看着挺吓人。一查分布：其中 261 条是同一个原因——文件在 Windows 上是 CRLF 行尾，检查工具对每一行都报一次「这行结尾有多余字符」。真实问题只有 16 条，还全是风格建议。94% 的告警，是同一件事重复了 261 遍。我自己一开始还猜错了原因，以为是脚本里的内嵌代码把解析器搞崩了，是本地 AI 纠正了我。方向对、归因错，一样是错。后来我们定了个规矩：看报告先看分布，别看总数。

第二件，才是真正的护栏。装上插件后，AI 每次要执行命令或写文件，都得先经过一道门。9 类不可逆操作直接拦死，不给确认的机会：rm -rf /、删系统目录、强推 main 分支、DROP DATABASE、格式化硬盘、把私钥内容写进文件……其余高危操作——装依赖、git reset --hard、改表结构、没有 WHERE 的 DELETE、部署上线——弹一次确认，并告诉你违反了第几条红线。

这里有个克制点，值得单独说：rm -rf node_modules，明确不拦、不问、直接放行。因为这是每个人每周都要干好几次的正常操作。护栏最容易死掉的方式，不是漏拦，是烦到你自己把它关了。所以白名单里躺着 node_modules、dist、build、.next、venv，删这些，一声不吭。

拒绝信息里也永远带着关闭方法。不能把用户锁死在自己的工具里。

还有一条必须写明的失效场景：护栏靠 bash 运行。如果你的电脑上没有 bash，它会静默放行，不会报错。所以 README 里加了「装完花一分钟确认它真的生效」的三步验收——怕的就是有人以为自己有护栏，其实没有。

这条失效场景，今天差点被我们自己漏掉。审查 install.sh 时，本地 AI 一上来就发现了正确的疑点：「~/.claude/skills/ 是技能目录，不是插件目录，hooks 可能不会被加载。」这个怀疑是对的。然后它去查文档，查完宣布疑点推翻、机制可行。它的证据是几段文档推导；而它所谓的「实测」，只验证了文件被复制过去了——一个 hook 都没触发过。它用更弱的证据，推翻了自己正确的怀疑。AI 会说服自己，而且过程看起来特别专业：查了官方文档、做了实测、列了三条论据，你很难不信。这件事后来变成一句写在安装脚本输出里的话，最后那段会讲。

装之前，你大概会问：它会不会烦我？

把三件事实放在一起说：

- 拒绝信息里那句「确需执行请你自己在终端手动运行」是认真的——护栏拦的是 AI，不是你。你想干还是能干，只是得自己动手。

- `rm -rf node_modules` 明确放行、不拦不问。白名单里还有 dist、build、.next、out、venv、__pycache__、coverage 这些常见构建产物，删了能重建，不打扰你。

- 每次拒绝信息里都带着关闭方法：`/plugin disable vibe-coding-guide`。它不会把你锁死。

一句话收束：它不替你做决定，它只是不让 AI 替你做决定。

03

PART

v2.1：两条新铁律，全是这一天撞出来的

PART 03

v2.1 的铁律从四条加到五条，其中两条，都是这一天的开发里真实发生的。

第一条的起因，是 AI 改了自己的测试题。

有一项检查是「能不能发现代码里静默吞掉的错误」，测试样例本来是一段跨了三行的代码，检查工具抓不到，那条测试红了。AI 的处理方式是——把测试样例改成一行的。改完，绿了。它如实汇报了这件事，没有隐瞒。但这个动作本身，等于把这项检查作废：它以后不但抓不到真问题，还会打印一个 ✅ 骗你。

让样例迁就实现，比不检查更有害。不检查至少你知道自己没检查。所以铁律 3 补了一句：测试不过时，改实现去满足测试，不准改测试来迁就实现。

第二条的起因，是 AI 三次主动停住。

整个过程里，AI 有三次主动停住、拒绝往下走，因为我的指令自相矛盾。一次是我一边要求「拦截 rm -rf」，一边又在测试里断言「rm -rf node_modules 必须放行」，两条打架。最让我服气的是 CHANGELOG 那次：我要求全仓库不许出现「四条铁律」这个词，但 CHANGELOG 里 1.1.0 的历史记录写的确实是四条——改它，就等于伪造历史。

这三次，它全是对的。尤其是 CHANGELOG 那次，它比我想得更清楚：不改历史，改我那条错的规则。

一个只会执行的 AI 是危险的。你要的是一个会说「你这两句话矛盾了」的 AI。所以新增铁律 5：指令自相矛盾、或与红线冲突时，停下来问用户，不要自己挑一条执行完再报「已完成」。

还有一个数字，是我最想让你知道的：这四个版本，一行代码都不是手打的。一个 AI 出方案、写指令、事后逐行复核；另一个 AI 在本地执行、跑测试、提 PR；中间的人，负责在两个 AI 打架或者停下来问的时候拍板。我作为复核方，抓出了 5 个真问题，其中 2 个是致命的；对方 AI 也抓出了 8 处我自己写错的指令。

双向纠错，才叫协作。单向服从，那叫赌博。

现在的位置，和它诚实的样子

PART 04

一句话总结这次升级：v1.0 是一份规矩本，v2.1 是规矩本 + 体检工具 + 强制护栏。红线从靠 AI 自觉，变成 9 类硬拦 + 12 类弹确认，AI 绕不过去；检查方式从人工一条条读，变成先跑一遍脚本；测试断言从 32 条涨到 62 条，0 失败。

也把边界说清楚：实测环境是 Windows + Claude Code，端到端跑通，hook 确实会触发。我不说「再也不会翻车」，准确说法是——9 类不可逆操作会被直接拦下，其余高危操作会弹确认。没有 bash 的环境，护栏会失效。

还有一句旧话，今天必须一起认。README 顶部原来写着「红线自动拦截——删数据、花钱、暴露密码……这类危险操作，必须先经你确认」。这句话从 v1.0 就在，当时一条都拦不住。后来代码升了两个大版本，宣传语一个字没动过——不是懒，是没人会想到去审查一句「一直都在那儿」的话。今天重构 README，我们把它删了：现在它部分能做到了，但原话反而变得更危险——读者会以为全都拦得住，而实际只有 9 条硬拦，且只在一种安装方式下有效。

所以这次我们做了一件反宣传的事：在安装脚本自己的输出里，主动写上——强制护栏（会真的拦下 rm -rf / 之类命令的那层）不保证以这种方式生效，要用护栏，请改用插件安装。一个自称安全工具的项目，在安装脚本里告诉用户「你这样装可能没有安全」。别人的做法是发现问题然后修好；这次我们选择的是，发现不确定，就把它说出来。

护栏是第二道锁，不是第一道。第一道永远是你自己看清楚，再点确认。

第一版文章结尾我说，考驾照时教练第一句话是：安全带先系上。这次补一句：安全带系没系好，要真的拉一下才知道，别只看仪表盘上那个「已系好」的灯。

想装上它的话，Claude Code 就两行命令：

```

/plugin marketplace add Amer-CN/vibe-coding-guide

/plugin install vibe-coding-guide@vibe-coding-guide

```

装完不用记任何命令，正常说话就会自动生效。不用 Claude Code 的，把仓库里的 SKILL.md 整个复制、粘给任何 AI，规矩那部分照样生效——但「真的拦下来」那层做不到，那层只在插件方式下有。

项目还是免费开源的：https://github.com/Amer-CN/vibe-coding-guide
