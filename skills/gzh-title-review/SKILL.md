# gzh-title-review

标题复盘是**发布后**动作：一篇文章表现不好（打开率/转发/完读低于预期），
先归因再行动——不要第一反应是「再改个标题」。

## 权限与范围声明（最小权限）

- **文件读写**：仅限调用方显式传入的标题/文章文本与 RUN 目录内评审产物。
- **网络访问**：无。**凭据**：无。**子进程**：无。
- **明确不做**：不改文章正文、不做发布动作、不安装依赖。

## 边界（明示）

- **流水线外独立工具**：不接 wxgzh-pipeline 编排器、不进 skills.lock.json、
  不参与任何发文验收；单装单用。
- 输入：正文 + 发布数据（打开率/转发/完读，缺失则如实标注「无数据」）。
- 输出：复盘结论 markdown，不自动改文，不做任何发布动作。

## 复盘四分类归因

每篇复盘必须落到且只落一类（可混「无法判断」，禁止兼落两个具体类）：

1. **标题因素**：标题承诺与正文供给错位、主标题被风格带偏、风险标记命中
   （标题党/堆砌/无据/时效，见 title-playbook 术语）。
2. **选题时机**：热点窗口已过、同题扎堆被分走注意力、读者群不在场。
3. **账号分发**：推送时段/频次/粉丝池错位，标题没问题但没推到对的人。
4. **无法判断**：数据缺失或样本太小，如实说不知道，禁止硬归因。

## 硬性规则（同我们气质）

- 无据不加：归因必须挂证据（数据/时间线/原文对照），证据不足 = 无法判断。
- 不吹推荐池：复盘结论是假设，不是打包票；每条结论标「可验证/待验证」。
- 一个主承诺：每篇只给一个最重要的下一次动作，不给十连清单。
- 保留作者语气：建议改的是标题承诺与供给的错配，不是把作者风格改成模板腔。

## 用法

```bash
# 把正文与数据交给任意支持 Agent Skills 的工具即可
# 或由人打开本目录 SKILL.md 人工执行复盘流程
```

## 流程

1. 读正文，重跑标题诊断：主判断是什么、标题承诺了什么、证据撑不撑。
2. 读发布数据（缺则标无数据）。
3. 对照四分类归因，标证据与可验证性。
4. 输出：归因 + 一个下一次动作 + 可复用规则（若有）。
