## 24. 规范化放在写作侧还是排版侧:结论与理由

**结论:职责归属 = 写作侧;落地路径 = 排版侧(渲染前)+ 守卫同步变换。**

- **职责论证(为什么是写作侧)**:标点字符是「内容」不是「样式」。半角引号出现在中文正文 = 内容质量问题,与数字格式、单位、时区一样属于写作/编辑职责(zh-human-writing「去 AI 味」阶段天然覆盖)。排版职责是把给定字符正确呈现,不应改字。
- **落地论证(为什么当前架构只能从排版侧落地)**:
  - 写作侧是 **agent 握手阶段**(super_writer / zh-human-writing 输出由 agent 生成)。代码侧没有「写文章」能力,只有校验器。把规范化写成 agent 执行约定(SKILL.md 指令)是**软约束**——档 53 已证明 LLM 风格漂移会绕开任何口头约定(本次即 AI 生成了 ASCII 引号)。
  - 在 zh-human-writing 输出后加**确定性后处理**(Pipeline 侧脚本改 final_article.md)会破坏该阶段的产物绑定语义(receipt 绑定 agent 产物 hash),且违反「禁止修改前四阶段产物」红线语义。
  - 排版侧(gzh-design 渲染)是**确定性代码路径**——规范化可以作为渲染管线的一步,可测试、可版本化、可审计。
- 因此:规范化**逻辑上属于写作侧,实现上落在渲染前**,以确定性函数执行;渲染产物与冻结文章的差异由守卫以「规范化等价」方式消化(见第 25 项)。

## 25. 与内容保真守卫的冲突:解法(不是放宽守卫)

**核心难点**:守卫(`_intro_content_fidelity` / INTRO_GUARD)逐字比对 final_article.md 段落与 final.html 反提取文本;规范化会改字,逐字比对必 FAIL。

**解法:双侧应用同一规范化函数后再断言**——把比对从「字面等价」升级为「规范化等价」:

1. 共享确定性函数 `normalize_cjk_punctuation(text)`(单一实现,见第 26 项规则;代码块感知:标记区不转)
2. 守卫比对流程变为:
   - `md_paras` = final_article.md 各段
   - `html_text` = final.html 反提取纯文本
   - 断言:`normalize(md_para) in normalize(html_text)`(逐段,全部段落)
3. **断言强度不变**:内容必须完整存在(仍是一段不少);只是比较前对两侧应用同一变换。这不是放宽——「内容保真」的语义从「字节一致」精确化为「规范化等价一致」,而规范化函数是公开、确定、可审计的(每个变换位置可记录)。
4. **代码块例外**:`<pre>`/等宽区内文本在渲染产物中保留原样;守卫比对时对 md 的代码块段落(围栏 ``` 内)跳过规范化(规范化函数对代码块标记区不转,两侧一致)。
5. 误报风险与对策:
   - 规范化函数与渲染器/守卫必须**同一份代码**(单点定义,禁止两侧各写一遍——OBS-31 教训「口径分裂」)
   - 若规范化规则未来变更:守卫与渲染器同步升级(同一函数),历史 receipt 不受影响(守卫只在新 RUN 执行)
   - 反向验证:三篇历史 RUN(含 vibe-coding-guide 大量 shell 命令)必须仍 PASS——代码块内 ASCII 引号不转,反提取文本与 md 代码块逐字一致

## 26. 规范化范围界定

**转(仅限「中文正文语境」)**:
- ASCII 双引号/单引号 `"` `'` → 全角 `“` `”` `‘` `’`(按配对与上下文;两侧均为中文或中文+标点时转)
- 中文后紧跟的半角逗号/分号/感叹号/问号 `,;!?` → 全角(与 validate_gzh_html HALF_PUNCT 同口径)

**绝不转(逐类说明)**:
- **代码块(fenced ``` / 行内 `code` / <pre> / 等宽样式区)**:shell 命令、程序输出字符串内的 ASCII 引号是语义字符,误转会破坏可复制性——vibe-coding-guide 那篇文章正文含大量 shell 命令与程序输出字符串,是**反向验证样本**
- **命令行/程序输出字符串**:同上
- **URL / 路径 / 文件名**:协议、查询串、路径分隔中的字符不变
- **英文原文引用内的引号**:引号两侧均非 CJK(英文语境)时保留 ASCII(中英混排不误伤)
- **数字、单位、时间、百分比格式**:只做引号/半角标点变换,不动任何数字字符
- **HTML 属性引号**:属性本就必须 ASCII(validate E_INVALID_ATTRIBUTE_QUOTE 反向规则),不属正文规范化

判定实现要点:代码块感知(围栏/反引号/pre 标签状态机)+ CJK 上下文判定 + URL 正则排除;全部规则收敛在**一个函数**内,输出同时提供 `transform_log`(每个变换位置:原文→新文),供审计与守卫诊断。
